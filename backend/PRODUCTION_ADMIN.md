# Create admin user for production

The admin user exists only in the database where the API runs. If you deployed the API on a **production server** (e.g. api-asset.stellarinfomatica.com), you must create an admin user in **that** database.

## Option 1: Run the script on the server

On the machine where the API runs (or any machine that can reach the production Postgres):

```bash
cd backend
export DATABASE_URL="postgres://USER:PASSWORD@HOST:PORT/postgres"
export ADMIN_EMAIL="admin"
export ADMIN_PASSWORD="your-secure-password"
node scripts/create-admin.js
```

Use the same `DATABASE_URL` your production API uses (e.g. from the API’s `.env` or environment).

## Option 2: SQL (if you have DB access)

Connect to the production Postgres and run (replace the password hash with one generated by bcrypt for your password):

```sql
-- Example: insert user and make them admin (password below is hash for 'noble12345')
INSERT INTO public.users (email, password_hash)
VALUES ('admin', '$2a$10$...')  -- use bcrypt hash of your password
ON CONFLICT (email) DO UPDATE SET password_hash = EXCLUDED.password_hash;

INSERT INTO public.admin_users (user_id)
SELECT id FROM public.users WHERE email = 'admin'
ON CONFLICT (user_id) DO NOTHING;
```

To generate a bcrypt hash locally: `node -e "console.log(require('bcryptjs').hashSync('noble12345', 10))"`

## After creating the admin

Log in at your frontend (e.g. https://assets.stellarinfomatica.com/login) with the same email and password you set.
